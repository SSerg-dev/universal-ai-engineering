# 05-01 — State, Checkpoint, Memory, and Concurrency Contracts

## Tasks

1. Record ADR-0007 before persistence implementation: turn-boundary resume, idempotent request keys, preallocated run IDs, private leases/fencing, optimistic versions, explicit scoped memory, expiry/purge, and atomic metadata audit.
2. Define strict snapshots, turns, bounded results, memory writes, reservations, audit payloads, and infrastructure-free store/executor/ID ports.
3. Validate duplicate and parallel turns, mismatched run IDs, invalid leases/lifetimes, cross-scope memory, content in audit, and compatibility. Run full validation before dependent implementation.

## Acceptance

- Content-bearing conversation state and metadata-only audit are explicit distinct schemas.
- Retention is an explicit bounded input, without an inferred default or human approval.
- Only one running turn appears per snapshot; private lease tokens cannot appear in public snapshots.
- Settled turn results match allocated run IDs. Memory scope/version/lifetime fits its conversation.
- Store ports describe atomic operations without importing PostgreSQL, transport, or provider types.

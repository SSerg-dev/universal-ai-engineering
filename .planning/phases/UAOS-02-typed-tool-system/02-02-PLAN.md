# 02-02 — Registry and Second Tool

Implement ADR-0004 through the normal runtime entry points and preserve Phase 1 behavior.

## Tasks

1. Implement immutable registration, allow-list checks, asynchronous input/output validation, bounded execution, cancellation, and seven normalized failure outcomes. Use failing regression tests for zero-call rejection, noncooperative handlers, late settlement, races, and concurrent policy isolation.
2. Reuse the existing agent loop for both iterations. Bind the Phase 1 facade to its search port and the Phase 2 facade to the registry. Persist version 1.1 diagnostics for registry failures while preserving public CLI/HTTP result fields and statuses.
3. Add read_doc against the existing controlled Markdown snapshot, the deterministic tool model, and explicit iteration 2 composition. Prove both tools and a third test-only registration run without loop changes. Exercise CLI/HTTP parity, safe JSONL, and invocation cancellation.
4. Write the Iteration 2 guide and evidence, update requirement traceability and changelog, and run the full validate gate before committing the summary. Phase 2 approval and stability remain pending until the user decides.

## Acceptance

- Duplicate names fail construction. Unknown, denied, and invalid-input invocations execute no handler.
- Invalid output and source projections become TOOL_OUTPUT_INVALID. Exceptions reveal only normalized codes.
- TOOL_TIMEOUT and TOOL_CANCELLED remain distinct, including already-aborted calls and late handler settlements. Timers and listeners are released.
- Registered input defaults/transforms reach the handler, and async schemas obey the same deadline.
- Tool failure prevents the second model request. Journal failure prevents later tool/model effects.
- The existing 90-test Phase 1 baseline remains green. Iteration 2 returns the same public result shape with tool diagnostics in safe version 1.1 events.
- Both supplied tools are runnable through CLI and HTTP. A third tool is added through registration alone.
- Project typecheck, core compilation, all tests, build, links, pins, and evidence checks pass on Node.js 24.

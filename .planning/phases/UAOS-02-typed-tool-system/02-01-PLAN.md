# 02-01 — Registry Contracts

Define the [typed registry ADR](../../../docs/architecture/decisions/ADR-0004-typed-tool-registry.md), schemas, defaulted generic model/journal ports, and a narrow tool dispatcher port before implementing dependent orchestration.

## Tasks

1. Define the invocation, observation, descriptor, typed failure, registered model action, and read_doc input/output schemas. Validate all seven failure codes and strict envelope boundaries.
2. Define event version 1.1 with validated tool names and safe tool error metadata. Keep the version 1.0 schema strict. Define ports that preserve existing callers through default type parameters.

## Acceptance

- Strict schemas accept valid transformed/defaulted arguments through each registered schema and reject unknown fields at public protocol boundaries.
- The invocation result discriminant preserves seven distinct failures and a typed successful observation.
- Version 1.0 continues to reject version 1.1 and non-search tool names. Version 1.1 rejects raw arguments, output, questions, documents, answers, and exception details in journal payloads.
- Project typecheck and core-only compilation pass. Existing Phase 1 tests retain their behavior.
- No dependency or lockfile changes occur.
